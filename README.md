# stem-sep — キーボード耳コピ用ステム分離

Ave Mujica / Roselia / MyGO!!!!! などの曲から Piano / Strings / Synth / Keys / Organ / Digital Piano / Chorus を抜き出し、
Audacity で並べて聴き比べるためのツール。**分離結果は個人の練習専用。アップロード・公開・Git へのコミットはしない。**

## 使い方

```bash
cd ~/music_split_server
./separate.sh inbox/song.flac            # 1曲
./separate.sh inbox/*.flac               # 複数曲（フォルダ指定 ./separate.sh inbox も可）
./separate.sh --force song.wav           # 既存の出力を無視して全ステップをやり直す
./separate.sh --explore song.wav         # Mega 53 の全53ステムを output/<曲名>/explore/ に保存
./separate.sh --optional song.wav        # 比較用モデルも実行（結果は work/alt_*.wav）
./separate.sh --clean song.wav           # 出力を作ったあと work/ を削除（容量節約）
.venv/bin/python check.py                # 全曲の出力を検証（output/<曲名> を指定してもよい）
./clip.sh inbox/song.flac 60 30          # 60秒目から30秒のテストクリップを inbox/clips/ に作成
./mixer.sh                               # ブラウザで聴くミキサーを起動（下の「ミキサー」を参照）
```

| オプション | 内容 |
|---|---|
| `--force` | 既存の出力があってもスキップせず再処理する |
| `--explore` | `config.yaml` の `explore.model`（Mega 53 フル版）を upper に適用し、全ステムを `explore/` に保存する |
| `--optional` | `optional: true` のステップ（比較用モデル）も実行する |
| `--clean` | 正常に終わった曲の `work/` を削除する。出力ファイルは残るが、次に実行すると全ステップをやり直す |
| `--keep-work` | 互換用。何も変わらない（`work/` はもともと残す） |
| `--config FILE` / `--output DIR` | 設定ファイル / 出力先を変える |

途中で失敗・中断しても、もう一度同じコマンドを実行すれば続きから処理する。
ステップの出力が揃っていて、入力より新しく、同じモデルで作られていればスキップする。入力やモデルが変わったステップと、それに依存するステップだけを再実行する。

## 処理の流れ（カスケード）

```text
入力 ─ffmpeg(soxr)→ original (44.1kHz/stereo/float32)
  │
  ├─[vocals]  BS-Roformer-Resurrection ─┬─ vocals ─┬─[karaoke] frazer&becruily ─→ lead / backing(=chorus)
  │                                      │          └─[mega_back_vocal] Mega53 back-vocal ─→ chorus-alt
  │                                      └─ instrumental
  │                                             │
  │                    [six_stem] BS-Roformer-SW: drums, bass, guitar, piano, other, (vocals)
  │                                             │
  │                    [upper] instrumental − drums − bass   (または guitar + piano + other)
  │                                             │
  │        ┌─────────────────┬─────────────────┼──────────────┬──────────────┐
  │   [strings]          [mega_synth]      [mega_keys]   [mega_organ]  [mega_digital_piano]
  │   gilliaan v1         Mega53 単ステム版（フル版と出力はビット単位で一致）
  ▼
output/<曲名>/<曲名>_<楽器名>.m4a  ＋ manifest.json ＋ log.txt
```

## 出力

```text
output/<曲名>/
├── <曲名>_original.m4a  原曲（変換・ゲイン調整後）
├── <曲名>_upper.m4a     ボーカル・ドラム・ベース抜き（耳コピの基準トラック）
├── <曲名>_keyboards.m4a キーボード系まとめ（upper − guitar。piano/strings/synth/organ 等を全部含む）
├── <曲名>_piano.m4a     BS-Roformer-SW の piano
├── <曲名>_strings.m4a   Bowed Strings 専用モデル
├── <曲名>_synth.m4a     Mega53 synth
├── <曲名>_keys.m4a      Mega53 keys
├── <曲名>_organ.m4a     Mega53 organ
├── <曲名>_digital-piano.m4a Mega53 digital-piano
├── <曲名>_chorus.m4a    karaoke モデルの backing
├── <曲名>_chorus-alt.m4a Mega53 back-vocal（vocals に適用）
├── <曲名>_lead.m4a      karaoke モデルの lead
├── mix/                  ミキサー用（lead / chorus / drums / bass / guitar / keyboards の .flac。全部足すと原曲）
├── manifest.json         使用モデル・sha256・各ステップの時間と VRAM・各ファイルのピーク/RMS
├── log.txt               実行ログ（各ステップの所要時間と VRAM ピーク）
├── explore/              --explore 時のみ（53ステム）
└── work/                 中間ファイル（vocals, instrumental, drums, bass, upper_subtract, upper_sum, alt_* …）
```

- 出力は **m4a（AAC 256kbps）**・44.1kHz・ステレオ・全ファイル同じ長さ。ステムごとの音量正規化はしない。
  形式は `config.yaml` の `output_format` で変えられる（`aac` / `alac`＝ロスレス m4a / `wav`＝32bit float）。
  `work/` と `explore/` は、モデルの入出力に使うので常に 32bit float WAV。
  AAC はファイル末尾に約13ms の無音の詰め物が付くが、先頭はそろっている（Audacity で並べてもずれない）。
- **何も検出されなかったパートは保存しない**（`drop_silent`）。判定は、そのファイルで一番大きい1秒間の RMS が、原曲の同じ値より 30dB 以上小さいとき。
  短いソロしか無いパートも、その1秒が大きければ残る。保存しなかったものは log.txt と manifest の `dropped_silent` に記録され、work/ には残る。
- どれかのファイルのピークが上限（AAC は -1dBFS、それ以外は 1.0）を超えた場合だけ、**全ファイルに同じゲイン**をかけて収める（`global_gain_on_clip`。パート間の音量関係は保たれる。かけたゲインは manifest の `global_gain` に記録される）。
- `wav` 形式のときは、内容が `work/` と同じファイルをハードリンクにしている（容量を食わない）。
- `mix/` は互いに重ならない6パート（`config.yaml` の `mixer.tracks`）。全部 0dB で足すと原曲に一致する
  （check.py が `work/original.wav` と比べて確認する。実測 −77〜−81dB の差）。
  AAC だと各パートの誤差が打ち消し合わず、足しても原曲と −26dB ほどずれるので、`output_format` に関係なく 16bit FLAC で保存する（1曲 約110MB）。
  ゲインは他の出力と共通なので、ミキサーで mix と個別パートを重ねても音量関係は正しい。

## ミキサー（スマホ・タブレット・PC のブラウザで聴く）

Moises のように、パートごとの音量を変えながら聴ける。同じ LAN（`192.168.15.x` の Wi-Fi など）の端末から使う。

```bash
./mixer.sh                 # ポート 8000 で起動。Ctrl+C で停止
./mixer.sh --port 8080     # ポートを変える
```

1. 起動すると `http://192.168.15.150:8000/?k=...` の形の URL が表示される。**各端末で一度だけ**この URL を開く
   （トークンが cookie に保存され、以後は `http://192.168.15.150:8000/` で開ける。ホーム画面に追加しておくと楽）。
   トークンは `.mixer_token` に保存されている。漏れたらこのファイルを消して再起動すると作り直され、全端末で再ログインが必要になる。
2. 最初はライブラリ画面（曲名・アーティスト・BPM・キー・長さの一覧。検索と、追加日順 / 曲名順の並べ替えができる）。曲をタップするとプレイヤーが開く。
   プレイヤー左上の ‹ でライブラリに戻る（再生は続き、下にミニプレイヤーが出る）。ブラウザの戻るボタンも使える。

### ノーツ表示（パートを MIDI にする）

プレイヤー右下の3つ目のボタン。YouTube のピアノ動画のように、上からノーツが落ちてきて鍵盤が光る（再生と同期。キーを移調しているとノーツも移調）。

1. 「MIDI を作る」でパートを選ぶ（初期状態はキーボード系とコーラスにチェック）。1パート 2秒ほどでできる。
   モデルは自動（初期値）・標準（Basic Pitch。どの楽器にも使える）・高精度（YourMT3+。1パート10〜30秒）・高精度・遅い（MuScriptor medium。1パート1〜2分）・ピアノ専用（ByteDance。分離したピアノでは標準より良いとは限らない）。
   自動はストリングスを MuScriptor、ボーカル・木管を YourMT3、ほかを標準で作る。
   MuScriptor はパートに入りうる楽器だけを聞き取らせる（ストリングスならヴァイオリン・ヴィオラ・チェロ・コントラバス・弦合奏）。
   ヴァイオリン実演奏5楽章のノート F1（±150ms）は 0.91（YourMT3 の方式 0.87）。天球のMúsica のストリングスでは 0.1秒未満の細切れが 51% → 1%、伸ばしの声部がつながる。
   以下の「高精度」の説明は YourMT3 の方式。ストリングスの高精度は、YourMT3 が落としがちな長く伸ばす音を Basic Pitch の結果から足す。
   実測（Bach Violin Dataset の実演奏5楽章、発音時刻 ±50ms のノート F1）: YourMT3 0.71 / Basic Pitch 0.58、±150ms で 0.90 / 0.76。
   ただし分離したベースと歪んだギターでは YourMT3 はほとんど音を出さないので、そこは標準のまま。
   高精度の結果は音（定数Q変換のスペクトル）と照らし合わせる: その瞬間いちばん強い音高より 22dB 以上弱い音は「聞こえていない音」として消し、
   同じ音高の細切れ（0.12秒以内で、間で音が途切れていないもの）は1本につなぎ、ストリングスは同時5声まで（強い音を残す）。
   天球のMúsica のストリングスで、ノーツ 2969 → 1991、同時発音の最大 8 → 5、スペクトルより 20dB 以上弱いノーツ 12% → 2%。ヴァイオリン実演奏での精度はほぼ変わらない（F1 0.695 → 0.690）。
2. 色分けしたパートのボタンで表示を切り替える。「表示」で見える長さ（1〜8秒）、ノーツの長さ、クオンタイズ（オフ / 8分 / 16分。検出した拍に合わせる）。
   ノーツの長さは初期状態で「打鍵ごとに区切る」: 同じパートの次の打鍵の少し手前でノーツを切るので、押すタイミングが分かりやすい（70ms 以内に始まる音は1つの和音とみなす）。
   「同じ音だけ区切る」「実際の長さ」も選べる。ノーツの下端（打鍵の瞬間）は明るく描く。
3. 「MIDI 保存」で表示中のパートを .mid に保存する（パートごとに1トラック、GM 音色付き。テンポの揺れをテンポマップに、拍子を拍子記号にして入れるので、DAW や MuseScore で小節線がそろう）。

- 自動の MIDI 化は「下書き」。そのままだと細切れの音や倍音のゴーストが混ざるので、楽器ごとに後処理している（音域外を削る、同じ音のつながった断片をつなぐ、短すぎ・弱すぎる音を消す、1・1.5・2 オクターブ上の弱い音を消す、リードは単音にしてビブラートの揺れを1音にまとめる）。
  キーボード系とギターは断片をつながない（同じ鍵盤の連打が1本の長いノーツにならないように）うえ、Basic Pitch の melodia trick（打鍵の無い「伸ばし」のノーツを足す処理）を切って、どのノーツも検出した打鍵になるようにしている。
  実測（天球のMúsica・FIRE BIRD）: ストリングスは 1分あたり 480 → 150 音、ピアノの長いノーツ（上位10%）は 1.24 → 0.74 秒、リードとコーラスは音の高さの線にほぼ重なる。細かいところは保存した MIDI を DAW で直す前提。
  どのモデルでも、トラックがいちばん大きいところより 45dB 以上小さい間の音は消す（静かな所に残る分離の残りかすが音符になるのを防ぐ）。
  MIDI 化の方法を変えたときは、作成済みのパートを開いたときに自動で作り直す。
- 結果は `output/<曲名>/notes/` にキャッシュされる（分離し直すと作り直しになる）。
- 入れ方は [models/MODELS.md](models/MODELS.md) の「ノーツ表示」。

### 曲の追加（ブラウザから分離）

ライブラリの **＋追加** で音声ファイル（m4a / mp3 / flac / wav / ogg / opus / aiff など、1GB まで）を選ぶ。PC ではライブラリ画面にドラッグ＆ドロップしてもよい。
スマホでは「ファイル」アプリなどから選べる（Apple Music の DRM 付きの曲は選べない）。

- ファイルを選ぶと **分離の設定** が開く（Moises と同じ構成。前回の設定を覚えている）。
  | 設定 | 出てくるトラック |
  |---|---|
  | 自動検出（初期値） | 鳴っている楽器だけ（下の「自動検出」） |
  | 耳コピ用（標準） | `config.yaml` のとおり（リード・コーラス・ドラム・ベース・ギター・キーボード ＋ ピアノ・弦・シンセなどの個別パート） |
  | ボーカル、ドラム、ベース、その他 | 4トラック |
  | ボーカル、インストゥルメンタル | 2トラック |
  | カスタム分離 | ボーカル（まとめて / リードとコーラス）、ドラム（まとめて / キック・スネア・タム・ハイハット・シンバル）、ベース、ギター（まとめて / アコギとエレキ）、ピアノ、キーボード、シンセ、オルガン、弦楽器、木管、金管 から選んだもの ＋ その他 |
  | 会話、サウンドトラック、効果音 | 動画・映画向けの3トラック |
  | HI-FI（スイッチ） | どの設定にも付けられる。各モデルを TTA（極性反転・左右入れ替えの3通りで推定して平均）で動かし、Audacity 用ファイルもロスレス（ALAC）にする。時間は約3倍 |

  カスタム分離は、選んだパートを「残り」から順に取り出していき、最後の残りを「その他」にする（`mixer/profiles.py`）。どの組み合わせでもトラックの合計は原曲と一致する（30秒のテストで全設定 −67〜−86dB）。
  何も入っていなかったパート（例: 木管のない曲の木管）は保存しない。設定は `output/<曲名>/separation.yaml` に残り、manifest にも記録される。
- **自動検出**: 候補の楽器（ボーカル・コーラス・ドラム・ベース・ギター・ピアノ・弦・木管・金管・オルガン・シンセ・キーボード）を全部カスタム分離と同じ順に取り出してから、
  「曲が鳴っている時間のうち、そのパートが曲全体から 15dB 以内で聞こえている割合」が 5% 未満のパートを、鳴っていないとみなして「その他」に足し戻す
  （コーラスが無ければリードに足して「ボーカル」にする）。足し戻すので合計は原曲のまま。
  コーラスは「声質で2つ」と「2人の歌い手」の両方で分けてみて、2つとも鳴っている（コーラスが鳴っている時間の 20% 以上で、コーラス全体から 6dB 以内）方を使う。どちらもだめなら1本のまま。
  モデルは11回（4〜5分の曲で約1分半）。判定の結果はログ（`detect:` の行）と manifest の `detection` に残り、曲の「…」に「見つからなかった」パートとして出る。
  しきい値は手元の3曲で決めた（鳴っていないパート 0〜1.6%、鳴っているパート 5.5% 以上）。設定は `mixer/profiles.py` の `AUTO_DETECT`。
- 曲の「…」→ **分離し直す** で、同じ曲を別の設定で分離し直せる（元ファイルから。終わっているモデルの処理は使い回す）。
- **パートをさらに分離**: プレイヤーのトラックの「…」→「さらに分離」で、そのパートだけを分け直せる（終わると自動で読み込み直す。進み具合はトラックの上に出る）。
  | パート | 分け方 |
  |---|---|
  | コーラス（分けたコーラスも） | 声質で2つ（声1・声2）／2人の歌い手（歌い手1・2）／4声（ソプラノ・アルト・テナー・バス。合唱用モデルで精度は低め） |
  | ボーカル（4トラックなど） | リードとコーラス（さらにコーラスを上のように分けられる） |
  | ドラム | キック・スネア・タム・ハイハット・シンバル |
  | ギター | アコギとエレキ |
  | キーボード / 上物 / その他 / インスト | ピアノ・弦・木管・金管・オルガン・シンセ・キーズ |

  分けた結果は足すと元のパートと同じ音になる（分けきれなかった音は「〜（残り）」。中身の無いものは保存しない）。分けたトラックの「…」→「〜にまとめ直す」で元に戻す。
  コーラスの分け方は、曲を追加するときの分離の設定でも選べる。設定は `profile.refine`（例 `{"chorus": "voice2", "drums": "kit"}`）として manifest に残る（`mixer/profiles.py` の `REFINE`）。
- ファイルは `inbox/` に保存され、サーバーが `./separate.sh` と同じ処理（パート分離 → 書き出し）と拍・コード解析を順に行う。一覧に進捗（今のステップと %）が出る。
  曲名はファイル名から決まり、同じ名前の曲があれば ` (2)` が付く。表示名・アーティスト・ジャケットはファイルのタグから。
- 複数追加すると1曲ずつ順番に処理する（GPU を使うので並列にはしない）。1曲 約70秒＋解析 約10秒（30秒のテストクリップで 23秒）。
- 失敗したときは一覧に理由が出る。「やり直す」で再実行（終わっていたステップは飛ばす）。
- 処理の途中でサーバーを止めても、次に起動したとき続きから処理する（ジョブの一覧は `.mixer_jobs.json`）。
- 端末で `./separate.sh` を実行して作った曲も、そのまま一覧に出る（ページを開き直すか、ライブラリに戻ると反映）。
- 曲の「…」→ **削除** で、`output/<曲名>/` を `output/.trash/<曲名>-<日時>/` に移す（元に戻すときはフォルダを戻すだけ）。`inbox/` の元ファイルは残る。
  `.trash/` は自動では消えないので、要らなくなったら手で消す。

| 場所 | 操作 |
|---|---|
| 上部 | ジャケット・曲名・アーティスト（元ファイルのタグから）。↺ ミックス・テンポ・キーを元に戻す、⤓ 書き出し、… マスター音量・クリック音量 |
| コード帯 | 拍ごとのマスと推定コード（小節ごとに区切り、拍子が変わる小節に `6/8` などを表示）。今の拍が白く光り、再生に合わせて流れる。マスをタップするとその拍へ移動 |
| トラック | lead / chorus / drums / bass / guitar / keyboards（全部 0dB で原曲と同じ）。楽器アイコンのタップでミュート、スライダーで音量（−40dB 以下で off、最大 +6dB）、… でパン・ソロ・0dB に戻す。波形タップで移動、**波形を横にドラッグすると区間選択**（そのままループする） |
| チップ | 原曲 / 上物 / ピアノ / ストリングスなど「重ねて聴く」パートを追加・削除する。ミックスの上に足されるので、キーボード耳コピなら「keyboards をソロ ＋ ピアノを追加」、原曲との聴き比べは「原曲を追加してソロ」 |
| 下部左 | メトロノーム（拍に合わせてクリック。小節の頭と小節内の強い拍にアクセント）、1234 カウントイン（再生前に今の拍子で1小節）、✂ 区間（今を始点/終点、今の小節）、⟲ ループ |
| BPM | テンポ変更（50〜150%、音程はそのまま）。**拍の補正**: 拍 ½倍 / 2倍、1小節の拍数（自動 / 2〜12）、小節の頭を1拍ずらす（検出がずれているとき） |
| ◀◀ ▶ ▶▶ | 5秒戻る / 再生・停止 / 5秒進む（PC はスペース、←→、L ループ、M メトロノーム） |
| キー | 半音単位で移調（±12）。コード名とキー表示も移調される。ボーカルは声質を保つ |
| 右下 | ミキサー表示 / コード表（小節ごとのコード一覧。タップでその小節へ） / ノーツ（下の「ノーツ表示」） |
| 書き出し | 今の音量・パン・ミュート・ソロ・マスター・テンポ・キーのとおりに混ぜて m4a（AAC 256kbps）をダウンロード。区間を選んでいれば区間だけも可（`<曲名>_mix_1m00-1m30_x0.8_+2.m4a`）。元の FLAC / m4a からサーバーで混ぜ直す。上限（−1dBFS）を超えるときは全体の音量を下げて収める |

- **拍・小節・コード・キー**は `mixer/analysis.py` がサーバー起動時に裏で推定する（1曲 約6〜9秒、GPU、`output/<曲名>/.mixer_cache/analysis.json`）。
  - 拍と小節: [beat_this](https://github.com/CPJKU/beat_this)（ISMIR 2024）の拍・小節頭の確率から `mixer/meter.py` が決める。
    テンポの揺れ（ライブ録音など）に追従し、beat_this が半分の速さで数えた区間は拍を補って、1マス＝1拍の長さをそろえる。
    1小節の拍数は 2〜7・9・12 のどれでもよく、**曲の途中で変わってもよい**（4/4、3/4、6/8、5/4、7/8 など。変わる回数は少ないほど、よく使う拍子ほど選ばれやすい）。
    小節の頭は beat_this の判定と「和音が切り替わる位置」の両方から決める。6/8 と 12/8 が混ざるときは 6/8 にそろえる。
    合成した 7/8・5/4（3+2 と 2+3）・6/8・4/4→3/4→4/4・4/4→6/8→4/4 のテスト曲では、小節線をすべて正しく検出した
    （キックを1拍目と4拍目に置いた不自然な 5/4 だけは 4/4 と判定した）
  - コード: [BTC](https://github.com/jayg996/BTC-ISMIR19)（ISMIR 2019 の Transformer、170 種: 7th / M7 / m7 / sus / dim / aug / 6 など）。
    原曲と「ドラム・リードを抜いた音」の両方にかけて平均し、各拍は後ろの8分を除いた部分で判定する（小節線の8分前に食って入るコードは、コード譜の書き方どおり次の小節の頭に置く）。
    最後に「コードは小節の頭で変わりやすく、次が小節内の強い拍（4/4 の3拍目、6/8 の4つ目、5/4 の3+2 の区切りなど）、ほかはまれ」という前提でならす（遅い曲では1拍ごとの変化も残る）
  - 表示は「…」→ コード表記で「詳しく（7th など）」「シンプル（三和音）」を切り替えられる
  - 拍子はコード帯・コード表の、拍子が変わる小節に小さく表示する（例 `6/8`）。BPM は 6/8・9/8・12/8 なら付点4分（`♩.=65 BPM`）で表示する
  - 拍が倍・半分に出たり、小節の区切りがずれたり、拍子の判定が違ったりしたら BPM ボタンの「拍の補正」（拍 ½倍 / 2倍、1小節の拍数を 2〜12 で固定、小節の頭を1拍ずらす）で直す（端末ごとに記憶）
  - メトロノームは小節の頭を強く、小節内の強い拍を中くらいに鳴らす。カウントインは今の小節の拍数ぶん鳴らす
  - 実測: 天球のMúsica 194 BPM・Dm・4/4（Moises は 195 BPM・Dm、C→Dm の位置も一致。途中に 5拍の小節が数か所出る）、FIRE BIRD 150 BPM・Gm・4/4、春日影 ♩.=65・B・6/8（`E E E F# F# F# | G#m` など）
  - 入れ方は [models/MODELS.md](models/MODELS.md) の「ミキサーの解析用」。どちらも無ければ librosa だけの方法（24種の三和音、精度は低い）で動く
- **テンポ・キー変更**はサーバーで ffmpeg の rubberband を使い、パートごとに変換する（1パート 6〜10秒、並列）。
  変換結果は `output/<曲名>/.mixer_cache/var/` に1曲あたり最近の3通りまで残る（1通り 約60MB × パート数）。変換後もパート同士のずれは数 ms 以内。
- 音はブラウザが 8秒ずつ取りに来る（1パートあたり約 1.4Mbps。off のパートは取りに来ない）。メモリに置くのも数十秒分だけなので、長い曲でもスマホで落ちない。
- 個別パートの m4a は最初に鳴らしたときに一度だけデコードされ、`.mixer_cache/` に置かれる（1パート 約55MB）。`.mixer_cache/` は丸ごと消してもよい（必要になれば作り直す）。
- フェーダー・パン・表示中のパート・区間・テンポ・キー・拍の補正・最後に開いた曲は端末ごとに記憶される（ブラウザの localStorage）。
- iPhone/iPad は画面をロックしたりブラウザを裏に回したりすると止まる（Web Audio の制限）。
- 合計がクリップしそうなときはマスターに軽いリミッターがかかる。
- 歌詞表示（Moises の歌詞ビュー）は無い。
- 外出先からは届かない（LAN 内専用）。外でも聴きたくなったら Tailscale を入れる（サーバーは `sudo` でインストールが必要）。
  ルーターのポート開放はしないこと（分離結果を外部に公開することになる）。

## 設定（config.yaml）

モデルの差し替え・保存するステム・chunk size などはすべて `config.yaml` で変えられる（コードの変更は不要）。

- `steps[].model`：`pymss list` に出る名前、または `pymss register` で登録した名前
- `steps[].outputs`：`{モデルのステム名: work/ に保存する名前}`。ステム名はモデル YAML の `training.instruments` を見る
- `steps[].inference_params`：`chunk_size` / `overlap_size` / `batch_size` などの上書き
- `upper_method`：`subtract`（instrumental − drums − bass）か `sum`（guitar + piano + other）。
  `work/upper_subtract.wav` と `work/upper_sum.wav` は常に両方作るので、聴き比べてから決めればよい。
  変更すると、upper を入力にしているステップだけが自動で再実行される。
- `deliverables`：楽器名と、その元になる work ファイルの対応（並び順もここで決まる）
  値をリストにすると足し合わせ、名前の前に `-` を付けると引き算（例 `keyboards: [upper, -guitar]`）。
  Mega53 の keys は piano とほぼ同じ音なので、個別ステムを足すとピアノが二重になる。キーボード系は引き算で作っている
- `song_overrides.<曲名>.merge`：その曲だけ、複数の楽器を1ファイルにまとめる（例 春日陰の `piano-strings: [piano, strings]`）
- `filename_pattern`：出力ファイル名の形。既定は `{song}_{part}`（例 `天球のmujica_strings.m4a`）。
  `{nn}_{song}_{part}` にすると先頭に通し番号が付き、ファイル一覧で番号順に並ぶ
- `explore.stems_per_pass`：explore を何ステムずつ処理するか（下の VRAM の項を参照）

## Audacity での推奨確認手順

1. `output/<曲名>/` の `<曲名>_*.m4a` を全部 Audacity にドラッグ＆ドロップする（トラック名＝ファイル名なので、楽器名で見分けられる）。
2. **upper をソロ**にして、上物全体の流れを掴む。
3. **piano → strings → synth / keys / organ / digital-piano** の順にソロで聴き、パートごとに音を拾う。
4. 迷ったら、そのパートと **original** を交互に（または両方）鳴らして、原曲で本当に鳴っているかを確かめる。
5. コーラスのハモりを拾うときは chorus と chorus-alt を聴き比べ、聴き取りやすいほうを使う。
6. 分離にはにじみが残る（例：synth に strings が少し混ざる）。複数のステムに同じフレーズが出たら、upper と原曲で判断する。

## Windows との受け渡し（共有なし：scp / WinSCP）

このサーバーではファイル共有を設定していない（ネットワークに公開されるディレクトリは無い）。
`<server>` はこのマシンの IP アドレスかホスト名（`hostname -I` で確認できる）。

**PowerShell（Windows 10/11 標準の OpenSSH）**
```powershell
# 曲を送る
scp "C:\Music\song.flac" vllm-admin@<server>:~/music_split_server/inbox/
# 結果を受け取る（フォルダごと）
scp -r "vllm-admin@<server>:~/music_split_server/output/<曲名>" "C:\Users\<you>\Music\stems\"
```
曲名に空白や記号が含まれるときは、リモート側のパスを `"..."` で囲む。うまくいかないときは WinSCP を使うのが確実。

**WinSCP**：新しいサイト → SFTP、ホスト `<server>`、ユーザー `vllm-admin` で接続 →
左（Windows）と右（`/home/vllm-admin/music_split_server/`）の間でドラッグ＆ドロップする。`inbox/` に置いて、`output/<曲名>/` を持ち帰る。
`work/` と `explore/` は大きいので、必要なときだけ持ち帰る。

Samba 共有（output は読み取り専用、inbox は書き込み可、LAN 内のみ・ゲスト無効）に切り替えたくなったら、
sudo が必要なので別途設定する。

## トラブルシュート

| 症状 | 対処 |
|---|---|
| `CUDA out of memory` | 他に GPU を使っているプロセスが無いか `nvidia-smi` で確認する。該当ステップの `inference_params` に `chunk_size` を小さめ（例 `441000`）に設定する。explore なら `stems_per_pass` を下げる |
| モデルのダウンロードが遅い・失敗する | `config.yaml` の `download_source` を `huggingface` / `modelscope` / `hf-mirror` に切り替える。手動なら `.venv/bin/pymss download <名前> --model-dir models --source huggingface` |
| 途中で止まった | 同じコマンドをもう一度実行する（終わっているステップはスキップされる）。原因は `output/<曲名>/log.txt` の `FAILED` 行とトレースバックを見る |
| 結果がおかしい・モデルを変えた | `--force` で全部やり直す。モデルを変えたステップと、それに依存するステップは自動で再実行される |
| check.py に `SILENT` が出る | その曲にそのパートが無い（例：オルガン不使用）ことが多い。エラーではなく警告 |
| check.py に `CLIP` が出る | 通常は `global_gain_on_clip: true` で自動的に防がれる。false にしている場合に出る |
| 容量が足りない | `--clean` で work/ を消す（1曲あたり 2〜3GB）。`explore/` も大きい（4分半の曲で 約5GB） |
| ffmpeg が無い | `sudo apt install ffmpeg` |
